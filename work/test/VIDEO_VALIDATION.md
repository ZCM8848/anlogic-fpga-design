# 钢珠检测/跟踪/计数 —— 离线录像验证记录

> 没有摄像头时，用**与 RTL 同参的等价管线**对桌面的实拍录像做验证。
> 脚本：`work/camera_hdmi_720p/tools/sim/cv_pipeline_sim.py`（检测=`cv_blkdet`，
> 跟踪=`cv_top` 的 a-b+贪心 NN，计数=`O_count` 轨迹消亡）。

## 管线（与当前 bit 一致）

```
块域(16x16)暗块检测(DARK_THR + 形状筛选: 面积8..400块 / 填充≥40% / 长短比≥50% / 贴边剔除)
  -> a-b 速度预测 + 贪心最近邻(GATE) 跟踪
  -> 计数：确认过的轨迹消亡(丢失>MISS_K) 时 +1
```

## 已定位的两个问题

1. **计数时序滞后（钢珠5）**
   规则是"轨迹丢失 > `MISS_K`(=20) 帧才 +1" → 计数**滞后约 20 帧、成堆跳**：
   有球帧段 5–42 / 191–237 / 355–394，而 +1 发生在 54/62/63 / 239/247/255/258 / 380/411/415。
   对照 `impl_a --count-mode exit`（**出画面即 +1**）：钢珠5 的 +1 落在 34/43/45…（与球离开同帧），
   时序正确；`cv_pipeline_sim.py --count-rule exit` 可复现。

2. **快球过计（钢珠3）**
   斜向快滚 + 相机移动时，a-b 预测 + 门限跟不上 → 同一球反复建轨 → 过计（8~10 vs 真值 3~4）。

## 修复（本轮）

1. **计数规则改为"出画面即计 + 消亡补计（去重）"**（对应 `cv_top` 的 `O_count`/`r_cnt_mask`）：
   - 预测位置出画面（`px_s<0 || px_s>=1280 || py_s<0 || py_s>=720`）→ **即时 +1**；
   - 未出画面的轨迹在消亡（丢失>MISS_K）时**补计一次**（`r_cnt_mask` 去重，新轨迹复位）。
   - 效果（`cv_pipeline_sim.py`，`min_hits=1`）：
     | 视频 | DARK | COUNT | 计数时刻 |
     |---|---|---|---|
     | 钢珠5 | 100 | **10** | 34/43/45 · 219/227/235/238 · 380/388/398（与球离开同帧）✅ |
     | 钢珠4 | 140 | **10** | 23/24 · 136/160/163 · 200/211 · 251 · 279/308（分散）✅ |

2. **暗阈值 `DARK_THR` 场景相关**（钢珠5=100、钢珠4=140）——**没有单一自适应规则能同时满足**
   （试过 min/max 中点、25% 分位、Otsu、分位数、mean-2std 都不行）。故：
   - 上板用**板载 K3/K4** 按现场调偏置（`DARK_THR=100` 基础 + 偏置，范围 0..2047）；
   - 或把 `DARK_THR` 作为按场景的构建参数。

3. 复现命令：
   ```bash
   python cv_pipeline_sim.py 钢珠5.mp4 out5.mp4 240 20 100 1   # COUNT=10
   python cv_pipeline_sim.py 钢珠4.mp4 out4.mp4 240 20 140 1   # COUNT=10
   ```
