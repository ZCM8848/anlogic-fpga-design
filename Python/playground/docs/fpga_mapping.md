# FPGA 映射（P1 估算，非 RTL）

目标：PH1P35MDG324，1280×720@60，75 MHz 像素域（每 4 个像素/行使能一次），
检测不占 DDR。所有资源均可用（用户确认）。

## 1. 模块划分

```
u_cam/u_isp ──G──┬─────────────────────────────────────────────┐
                 │                                             │
                 ▼                                             ▼
        [4×4 降采样 320×180]                            [HDMI/OSD 插入]
                 │                                             ▲
                 ▼                                             │
        [背景差分 |G−BG|] ──> [阈值 30] ──> [3×3 close/open] ──┤
                 │                                             │
                 ▼                                             │
        [游程 CCL + 并查集] ──> [碎片合并/固定框] ──> [跟踪 16] ──┘
                 │                                             
                 └──> [门线计数 x=0.30W] ──> 计数/事件
```

- 背景图 320×180×8 bit，预置或开机采集；IIR 更新。
- OSD 在 HDMI 像素域叠加；框/ID/计数来自帧尾更新，双缓冲。
- 参数/计数通过寄存器（APB/AXI-Lite 或现有配置总线）读出。

## 2. 资源估算（320×180 检测）

| 资源 | 估算 | 说明 |
|---|---|---|
| LUT4 | **12k–18k** | 降采样、差分、形态学、CCL、跟踪、OSD |
| DFF | 8k–12k | 流水/表项 |
| ERAM20K | **30–45 块**（共 108） | 背景 23 + 行缓存/CCL/轨迹/字体 |
| DSP | 2–4 | 可选：质心倒数、OSD 缩放 |
| 时钟 | 75 MHz 像素域 + 100 MHz 帧尾 | 4× enable；跟踪串行 |
| DDR | **不用** | 背景/行缓存全在 ERAM |
| 延迟 | ~2 帧 | 检测 1 帧 + OSD 双缓冲 1 帧 |

### 背景存储

`320 × 180 × 8 = 460,800 bit = 23.0 × ERAM20K`。剩余 60+ 块给形态学行缓存、
CCL 表、OSD 字体，余量充足。

### 行缓存

- 4×4 降采样：4 行 ×1280×8 = 40 Kbit（2 块）。
- 3×3 close/open：4 行 ×320×8 = 10 Kbit（1 块，复用）。
- 背景/差分：2 行 ×320×8 = 5 Kbit。

### CCL 表

- run 数上限：每行 ≤64 run，活动 run ≤256；并查集 1024 项 ×10 bit = 10 Kbit。
- blob 统计：1024 项 ×（area 16 + bbox 4×9 + sum 2×20）= ~100 Kbit（5 块）。
- 帧尾串行输出，和检测流水解耦。

### 跟踪/计数

- 16 条轨迹 ×（id 8 + cx/cy 11 + vx/vy 12 + hits/misses 4 + box 4×11 + flags）
  ≈ 1.5 Kbit；1 块。
- 运动门控：每条轨迹 5 个 `cx` 历史（5×11 bit）+ `moved/window_move`；
  16 条共 <1 Kbit。
- 距离平方 18 bit，16×16 串行比较；100 MHz 下 <3 µs。
- 门线比较器 + 计数寄存器，逻辑级。

### OSD

- 16 个框 + ID + 计数；8×16 字库 128 字符 = 16 Kbit（1 块）。
- 矩形/文本叠加在 720p 像素流；2–3 块。

## 3. 位宽/舍入

| 量 | 位宽 | 规则 |
|---|---|---|
| G | 8 | full range 0–255 |
| 4×4 和 | 12 | 16 像素和 |
| 降采样 | 8 | `(sum+8)>>4` |
| 背景 | 8 | clamp 0–255 |
| 差分 | 8 | 绝对差 |
| 面积 | 16 | 320×180 最大 57,600 |
| 质心 | 11（0–319/179） | `sum/area` 向下取整 |
| 速度 | 12 signed | `(v+delta)>>1` 算术右移 |
| 距离平方 | 18 | 不取 sqrt |
| 计数 | 16 | 每段最多数百 |

## 4. 时序/接口

- **像素域 75 MHz**：降采样、背景差分、阈值、形态学、CCL 写入。
- **帧尾 100 MHz**：CCL 收尾、blob 合并、跟踪、门线计数；与像素域用
  frame_start/frame_end 握手 + 双缓冲。
- **OSD 75 MHz**：读取上一帧的框表；跨到 HDMI 像素域。
- 现有设计在 MIPI 字节域已有 −1.83 ns Setup 违例；本模块不进入 103.5 MHz 域，
  只增加 75 MHz 像素域和帧尾逻辑，避免加剧。
- 输入取 debayer 后的 G；若直接取 RAW10，需要先用同一 Bayer 相位，建议不这样做。

## 5. 与 Python 逐位一致的检查点

1. `downscale4`：`(sum+8)>>4`。
2. 背景：`diff=|g-bg|`；`diff<10` 才更新；`bg += (g-bg)>>4`；clamp。
3. `diff>=30` → 形态学 3×3 close/open。
4. CCL：run 并查集；面积/质心整数公式；过滤阈值。
5. 合并：中心距 `<0.8D`；面积加权质心。
6. 跟踪：预测、贪心、`v=(v+delta)//2`、hits/misses。
7. 运动门控：`moved≥0.2D`、`window_move≤−0.5D`、`vx≤−4`；静态轨迹删除。
8. 门线：`prev_cx>xg && cx<=xg`，y 范围，一次性锁存。

## 6. 风险

- **时序**：75 MHz 像素域路径短，但 CCL 并查集/多表项访问可能成为瓶颈；
  必要时把 CCL 放到 100 MHz 帧尾，用行缓存 FIFO 解耦。
- **背景采集**：部署时必须无球采集；若背景含球，会产生幽灵。Web 端用预计算
  中值背景规避。
- **密集合并**：0.8D 合并阈值在透视压缩时可能误合并两球；需用标注真值调。
- **OSD 字体/中文**：当前 Python 用 OpenCV 英文；RTL 只需数字/ID，字库可最小化。
- **参数标定**：当前 40 mm 标定得到 D≈171 px；上板前用标定页再确认。
