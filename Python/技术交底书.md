## 1. 项目背景与目标

### 1.1 背景
赛题二要求以安路 PH1P35 FPGA 为核心，构建“MIPI 视频采集 → 图像处理 → HDMI 显示”的实时系统，并在基础要求之外鼓励实现**目标跟踪与信息标注**、**运动目标检测与计数**等进阶功能；评分标准特别强调**“光线剧烈变化时工作正常”**。

### 1.2 设计目标
针对“钢珠从一个方向滚入视野、再滚出视野”的场景，实现：

1. **全过程跟踪**：任一钢珠从进入视野到离开视野，始终保持同一 ID、同一识别框；识别框右上角标注钢珠 ID。
2. **计数**：对滚过视野的钢珠计数，并在 OSD 上显示。
3. **抗环境光**：尽可能降低对外界环境光变化的敏感度。

### 1.3 项目定位
本项目当前产出为**算法验证原型**：先用 Python + 传统 CV 算法在笔记本摄像头/离线视频上验证“检测—跟踪—计数—OSD”整条链路的可行性与参数，并**按其可硬件化的形式组织代码**，为后续在 PH1P35 上的 Verilog/硬件实现提供直接依据（详见第 8 节）。

## 2. 系统总体方案

### 2.1 最终 FPGA 系统（目标形态）
```
MIPI 摄像头(SC500CS/SC520CS) → 图像采集/解码 → 帧缓存(SDRAM/片内RAM)
   → 图像预处理流水线(灰度/滤波/二值化等, 硬件并行)
   → 目标检测(运动前景/形状筛选) → 目标跟踪(ID 管理) → 计数
   → OSD 叠加(方框/ID/计数/“安路”Logo) → HDMI 1280×720@60 输出
```

### 2.2 本验证原型（当前交付）
```
USB 摄像头(1280×720@60, MJPG) ──采集线程──▶ 最新帧
   → 下采样(处理分辨率 640×360)
   → 预处理: 灰度 + 光照归一化 [+ 可选 CLAHE]
   → 检测: [motion 模式] MOG2 前景 ∪ 帧差, 形态学, 颜色门, 面积/圆度/填充/长宽比筛选
           [hough  模式] 霍夫圆 + “圆内须为暗块”校验
   → 多目标跟踪: 匀速预测 + 门限最近邻匹配 + 遮挡补位 + 方向约束
   → 计数: [line 模式] 计数线穿越  /  [exit 模式] 轨迹离开视野计数
   → OSD: 方框 + 右上角 ID + 计数 + 计数线 + Logo
   → 显示 / 录制
```

## 3. 算法原理与流程

### 3.1 图像预处理
- **灰度化**：`Y = 0.299R + 0.587G + 0.114B`（硬件用定点 `(77R+150G+29B)>>8`）。
- **光照归一化**：`norm = gray / (GaussianBlur(gray, σ=25) + 1) × 128`。
  用大核模糊估计**低频照度**，再用当前像素除以该照度，从而消除光照不均与整体明暗漂移；这是抗环境光的核心手段。
- 可选 CLAHE 局部对比度增强（资源较大，FPGA 上默认不启用）。

### 3.2 目标检测

#### 模式 A：运动前景（`motion`，默认）
1. **背景建模**：MOG2，**建在光照归一化图上**（关键：避免全局亮度/自动曝光变化把整片区域误判为前景）。
2. **帧差**（可选，默认关）：对纹理背景噪声较大。
3. **ROI 掩膜**：限定到钢珠滚动带，压制静止背景与反光。
4. **形态学**：开运算去碎点、闭运算连通；**竖向开运算**去水平细条（高对比边界在光照微变下产生的伪影）。
5. **连通域筛选**：面积（由钢珠直径推出 `面积∈π(d/2)²·(1±tol)`）、圆度 `4πA/P²`、外接矩形填充率、**长宽比**。
6. **颜色门**：金属钢珠呈低饱和（银灰），人手/彩色运动物体饱和度高 → 用 HSV 饱和度上限剔除。
7. **质心与半径**：图像矩求质心，`r=√(A/π)`。

#### 模式 B：霍夫圆 + 暗度校验（`hough`）
适用于**“深色球在浅色背景、相机可能平移、球快或相互接触”**的场景（此时运动建模失效）：
1. 光照归一化 → 中值滤波；
2. `cv2.HoughCircles` 检测圆（可**分开相互接触的球**）；
3. **暗度校验**：圆内平均灰度须明显小于背景、且“暗像素”占比足够 → 压制木纹/纹理造成的虚假圆。

### 3.3 多目标跟踪
- 每个 `Track` 状态：ID、位置、速度（指数平滑 EMA）、半径、命中数、丢失数、状态、出生侧、是否越线。
- **预测**：`pred = pos + vel`。
- **关联**：预测点与检测点做**带门限的贪心最近邻匹配**（目标数少时等价于匈牙利；门限 = `max_gate × 半径`）。
- **生命周期**：连续 `min_hits` 帧命中后确认并分配 ID；连续 `max_coast` 帧未命中则删除。
- **遮挡/摩接**：未匹配轨迹用预测位置“滑行”，分离后可重新关联，**ID 不丢**。
- **方向约束**：单方向场景下抑制持续反向的干扰轨迹。

### 3.4 计数

#### 模式 `line`（计数线穿越）
- 定义与运动方向垂直的虚拟计数线；
- 轨迹质心越过该线、且运动方向与期望方向一致时 `+1`；
- **出生侧判据**：记录轨迹“出生时所在的侧”，确认后只要到达另一侧即认为越线 —— 补偿“目标在被确认之前就已穿过计数线”导致的漏计。
- 每条轨迹一个 `crossed` 标志，防止重复计数。

#### 模式 `exit`（离开视野计数）
- 一条已被确认的轨迹从画面中消失（离开视野）时计一次；
- 相机平移、运动方向不固定时比固定计数线更稳。

### 3.5 OSD 叠加
- 每颗钢珠：矩形框 + **框右上角** ID 标签（带底色的数字）；
- 左上角显示 `Count: N`；
- 叠加计数线与方向箭头；
- 右下角预留“安路/AL”标识位（FPGA 版用硬件叠加真实 Logo）。

## 4. 关键参数（节选，全部集中在 `config.py` / `config.json`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `proc_scale` | 0.5 | 处理分辨率缩放（640×360）|
| `ball_diam_px` | 80 | 钢珠直径（全分辨率像素，标定测量）|
| `area_tol` | 0.6 | 面积容差 |
| `min_circularity` / `min_fill` / `max_aspect` | 0.35 / 0.45 / 2.5 | 形状筛选门限 |
| `use_color_gate` / `max_sat` | true / 90 | 颜色门（剔除非金属）|
| `var_threshold` | 26 | MOG2 方差阈值 |
| `destreak` | true | 竖向开运算去水平细条 |
| `detector_mode` | motion | 检测模式 motion / hough |
| `count_mode` | line | 计数模式 line / exit |
| `min_hits` / `max_coast` / `max_gate` | 3 / 8 / 2.5 | 跟踪确认/补位/关联门限 |
| `use_illum_norm` / `illum_sigma` | true / 25 | 光照归一化 |

## 5. 测试与验证

测试素材为 5 段桌面钢珠实拍视频（1280×720），验证环境为本机 Python 3.11 + OpenCV 5.0 + numpy 2.4。

| 素材 | 分辨率/帧率 | 合规 | 场景 | 推荐命令 | 计数 |
|---|---|---|---|---|---|
| 钢珠.mp4 | 1280×720@30 | ✗(帧率) | 单球沿桌沿滚，手指入镜 | 默认 | 6（手指被忽略）|
| 钢珠2.mp4 | 1280×720@30 | ✗(帧率) | 2~3 球同轨道 | 默认 | 9 |
| 钢珠3.mp4 | 1280×720@30 | ✗(帧率) | 3 球斜向快滚 | `--ball-diam 120` | 4 |
| 钢珠4.mp4 | 1280×720@**60** | ✓ | 相机平移 + 多批球（真值 10）| `--detector hough --count-mode exit` | **10 ✅** |
| 钢珠5.mp4 | 1280×720@**60** | ✓ | 深色球浅背景、分批、相机移动（真值 10）| `--detector hough --count-mode exit` | **10 ✅** |

补充：合成测试视频（`simulate.py` 生成）真值过线 10 颗，系统计数 10（100%）。

**结论**：
- 分辨率 1280×720 与赛题基准一致（合规）；帧率 60fps 的素材表现明显优于 30fps（每帧位移减半、拖影减半、跟踪更连续）。
- 相机固定、单方向滚动的标准场景下，默认 `motion` 模式即可稳定跟踪与计数；
- 相机移动、球快/接触、深色球浅背景的场景，采用 `hough` + `exit` 模式可显著提升准确率。

## 6. 关键技术点与创新

1. **纯传统 CV、无 AI**：仅用背景建模/帧差/形态学/霍夫圆/连通域/矩特征/卡尔曼式预测等经典方法，算法规模小、可硬件化。
2. **光照归一化 + 背景建模建在归一化图上**：同时抵抗“光照不均”与“全局亮度/自动曝光漂移”，直接对应赛题“光线剧烈变化时工作正常”的评分点。
3. **多线索融合检测**：面积（尺度上限剔除人手）/圆度/填充率/长宽比/**颜色门**多线索联合判定，鲁棒剔除干扰物。
4. **竖向去条伪影**：针对高对比边界在光照微变下产生的水平细条，用竖向开运算去除，避免钢珠与伪影粘连而漏检。
5. **两种检测模式自适应**：运动前景（固定机位）与霍夫圆+暗度校验（移动机位/接触球）按场景切换。
6. **两种计数模式**：计数线穿越（含“出生侧判据”补偿确认前越线）与离开视野计数（相机平移更稳）。
7. **遮挡补位保 ID**：轨跡滑行机制保证摩接/短暂丢检时 ID 不跳变。
8. **可标定、可调参、可离线回放**：提供交互标定（ROI/计数线/方向/直径）、实时调试掩膜、录制与离线回放工具，保证现场可快速整定。

## 7. FPGA 移植方案（PH1P35）

| 本原型模块 | 硬件实现建议 |
|---|---|
| 下采样 / 灰度 | 行缓存 + 定点灰度 `(77R+150G+29B)>>8` |
| 光照归一化 | 降采样背景缓存 + 双线性插值近似大核均值；除法用倒数 LUT |
| 背景建模(MOG2) | 用 IIR 滑动均值 `bg=bg*(1-α)+cur*α`，`absdiff` 后阈值 |
| 帧差 | 行缓存保存 N-2 帧所需行（或整帧缓存）后做差分比较 |
| 形态学 / 去条 | 3×3 结构元 + 比较器/与或逻辑（竖向开运算用列方向窗口）|
| 连通域 + 面积/包围盒/周长 | 行 run-length 标记 + 并查集合并，边扫描边统计 |
| 颜色门 | 定点 RGB→S 近似，与阈值比较 |
| 目标跟踪（预测/匹配）| 每条轨迹一组寄存器(id,x,y,vx,vy,r,hits,miss)；距离平方比较 + 小规模并行仲裁 |
| 计数 | 计数线：直线方程符号比较 + 一位触发器；离开计数：轨迹有效位下降沿 |
| OSD 叠加 | HDMI 输出侧图形发生器：方框用计数器波门，ID 用字模 ROM，Logo 用位图 ROM |

设计取舍：MOG2/大核高斯/CLAHE 在 FPGA 上资源开销较大或不易实现，已给出**硬件友好替代方案**（IIR 背景、降采样背景缓存、跳过 CLAHE）。移植主线建议为：**帧差 + IIR 背景 + ROI + 形状/颜色筛选 + 跟踪 + 计数**。

## 8. 文件构成与使用说明

目录结构（程序统一置于 `Python/` 子目录，视频素材统一置于 `钢珠视频/` 子目录）：
```
ball_track/
├── Python/                 # 全部程序
│   ├── main.py             # 主程序: 采集线程 + 处理循环 + OSD + 录制
│   ├── config.py           # 全部参数(可 json 存取)
│   ├── preprocess.py       # 灰度 / 光照归一化 / CLAHE
│   ├── detector.py         # 检测(motion / hough 两种模式)
│   ├── tracker.py          # 多目标跟踪
│   ├── counter.py          # 计数(line / exit 两种模式)
│   ├── osd.py              # OSD 叠加
│   ├── calibration.py      # 交互标定 ROI/计数线/方向/直径
│   ├── preview.py          # 纯摄像头预览
│   ├── capture_check.py    # 采集合规性自检(实测真实帧率)
│   ├── probe_video.py      # 检查任意视频分辨率/帧率/编码是否合规
│   ├── to_720p60.py        # 视频转 1280x720(可统一 60fps)
│   ├── list_cameras.py     # 摄像头探测
│   ├── simulate.py         # 合成测试视频
│   ├── requirements.txt    # 依赖: numpy, opencv-python, (可选)Pillow
│   └── README.md           # 使用说明
├── 钢珠视频/                # 全部测试素材与结果视频 (*.mp4)
└── 技术交底书.md            # 本文档
```

常用命令（在 `ball_track/Python/` 下执行；视频路径经由 `..\钢珠视频\` 引用）：
```bash
pip install -r requirements.txt
python main.py                          # 默认摄像头(外接优先)实时运行
python main.py --camera 1               # 指定摄像头
python main.py --calibrate              # 交互标定
python main.py --video ..\钢珠视频\ball_real5.mp4 --detector hough --count-mode exit --output ..\钢珠视频\out.mp4
python capture_check.py --camera 1      # 采集合规性自检
python probe_video.py ..\钢珠视频\some.mp4   # 检查视频是否 1280x720@60
```
